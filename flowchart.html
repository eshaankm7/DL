Main Pipeline: 7-Module Processing Flow

Input: Traffic State Snapshot

Input tensor shape: 12 x 8 per timestep

Single-step lane matrix from simulation or CV pipeline

  • Supports offline dataset and live camera-derived tokens
  • Compatible with multi-lane mixed traffic
  • Ready for model inference after normalization
↓
M1

Data Generation Engine

SUMO + Synthetic Hybrid Source

  • Builds lane-level state transitions
  • Models three demand regimes
  • Captures two-wheeler heavy dynamics
  • Exports timestep records for training
↓
M2

Dataset and Loader Pipeline

Normalization + Split + Batch Delivery

  • Feature scaling via per-feature mean and std
  • Train/validation/test split: 70/15/15
  • Grouping by timestep into lane token matrix
  • PyTorch DataLoaders with batch size 128
↓
M3

LAAN Transformer Trainer

Lane-Aware Attention Learning

  • d_model 128, 4 heads, 3 encoder layers
  • Approx. 95k parameters
  • AdamW optimizer with early stopping
  • Predicts one of four traffic phases
↓
M4

Ablation Validation Module

Feature Contribution Verification

  • Trains ablated model with two_wheeler_ratio removed
  • Same architecture for fair comparison
  • Generates full vs ablated performance reports
  • Confirms impact of lane-aware two-wheeler cue
↓
M5

Evaluation Engine

Controller-Level Benchmarking

  • Compares fixed-timer, LAAN, and oracle policies
  • Simulates wait penalties under wrong phase selection
  • Metrics: average wait, P95 wait, LOS, accuracy
  • Produces evaluation_results.json for dashboard use
↓
M6

CV Inference Pipeline

Camera to Lane Token Conversion

  • IPM transform to bird's-eye view
  • Lane detection + MOG2 stall cues
  • YOLOv8 vehicle detection and lane assignment
  • Real-time feature token computation for inference
↓
M7

Dashboard and Deployment Layer

Streamlit Analytics Interface

  • Pipeline view and live inference preview
  • Results comparison and LOS summaries
  • Training curves for full and ablation models
  • Scenario-level breakdown and export support
↓

Output: Signal Decision Package

Traffic phase recommendation for real-time control

  • Predicted phase: 0, 1, 2, or 3
  • Confidence scores and probability distribution
  • Wait-time performance versus baseline controller
  • Dashboard-ready metrics and experiment artifacts
Operational Loop: Monitoring and Model Refresh
R

Periodic Refresh and Drift Monitoring

Reliability and Adaptation Guardrail

  • Monitors shifts in queue patterns and phase mismatch frequency
  • Triggers retraining when performance drops under threshold
  • Revalidates two-wheeler feature contribution via ablation reruns
  • Keeps checkpoints synchronized with evaluation reports
Key Innovations

Lane-Aware Tokenization

Each lane contributes a structured 8-feature token, enabling localized reasoning in dense mixed traffic.

Two-Wheeler Ratio Signal

A dedicated mixed-traffic feature validated through ablation to improve phase selection behavior.

CV-to-Control Integration

Computer vision outputs are translated into the same lane-token format used for model training.

Evaluation-First Reliability

Three-way controller comparison and scenario-level reporting provide transparent deployment confidence.
